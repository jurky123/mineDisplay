# Minecraft In-World Image/Video Display Mods — Reuse Notes

## Which open source mods render images/video in-world, and how does each get pixels on screen?

### Takeaway
Two technical families dominate: (A) Chromium/CEF browser-texture mods (WebDisplays lineage, including server-rendered WebDisplaysTogether) and (B) VLC/LibVLC-decoded video-texture mods (WATERFrAMES/LittleFrames/VideoPlayer/watervision) plus lightweight URL-image frame mods (PicAxe, Modern Online Picture Frames, Projector, webstreamer HLS/FFmpeg); only WebDisplaysTogether renders on the server and streams video, all others render per-client.

### Cited Findings
- WebDisplays (original by montoyo, now CinemaMod Group) is "a mod for creating and interacting with web browsers in Minecraft. You can create screens in your world and browse the internet" — [Source](https://github.com/CinemaMod/webdisplays)
- CinemaMod/webdisplays is forked from montoyo/webdisplays, has 73 stars / 45 forks / 256 commits on branch 1.20 — [Source](https://github.com/CinemaMod/webdisplays)
- WebDisplays content model includes placeable screen blocks, MinePad handheld tablet, keyboard/remote/redstone controller peripherals, laser pointer interaction, multi-block tiled large screens with configurable resolution, Miniserv file-host server, upgrades/advancements — [Source](https://github.com/mekos2772/webdisplays)
- Classic WebDisplays pixel path is per-client Chromium offscreen browser composited to an in-world block-entity texture; each client browses independently (no built-in sync), with known long-standing bug "screens blank out at certain camera angles" fixed in forks "by switching to a custom render path that bypasses Minecraft's per-section block-entity culling" — [Source](https://github.com/brother-bill/webdisplays-mc/releases)
- WebDisplaysTogether is "Watch the web together. The web page runs on the server and is streamed to every player as video — everyone sees exactly the same picture, at the same time" — [Source](https://github.com/He-Horatio/WebDisplaysTogether)
- WebDisplaysTogether architecture: "One shared browser per screen. The page runs in a headless Chromium instance on the server. Every player sees the identical frame, logins are shared, and playback stays in sync" with "Adaptive video. VP8/VP9 video and Opus audio, 30 fps, resolution scaled automatically between 360p and 1080p from server load and per-viewer network feedback" — [Source](https://github.com/He-Horatio/WebDisplaysTogether)
- WebDisplaysTogether also has "Screen audio ... from the screen itself, from placeable speaker blocks positioned in 3D, or straight to the player", "Multiblock screens from 2x2 up to 16x16, keyboards, a laser pointer for remote clicking, upgrade components, redstone interaction, a per-screen permission system, and a built-in file host", "Incognito by default. Cookies and logins stay in memory and are wiped when the server stops" — [Source](https://github.com/He-Horatio/WebDisplaysTogether)
- WebDisplaysTogether "contains no networking code of its own and never downloads anything" for the Chromium runtime install (server owner installs java-cef natives manually); "The build merges the bytedeco JavaCPP + FFmpeg classes and natives for windows-x86_64, linux-x86_64 and linux-arm64 into the mod jar" (~44.9 MB jar) for its video pipeline — [Source](https://github.com/He-Horatio/WebDisplaysTogether)
- MCEF is "a mod and library for adding the Chromium web browser into Minecraft" based on "java-cef ... based on CEF ... based on Chromium", "Current Chromium version: 116.0.5845.190" — [Source](https://github.com/CinemaMod/mcef)
- WATERFrAMES is "the mod to play videos and show pictures in your Minecraft worlds only using URLs powered by WATERMeDIA. Inspired on LittlePictureFrames", with "Multiple ways to show images (Frames, Projectors, TVs and Big TVs)", "Items and commands to control the frames from far away", "Local files support (powered by WATERMeDIA)", "Fully customizable ... rotating it, reducing brightness, making it transparent or having a custom audio distance" and "fully designed to work in survival mode" — [Source](https://github.com/SrRapero720/waterframes/blob/1.20.1/README.md)
- WATERFrAMES project has 49 stars / 42 forks / 615 commits, default branch 1.20.1 — [Source](https://github.com/SrRapero720/waterframes)
- WATERMeDIA is "Library with an API using VLC for multimedia integration with Minecraft" / "a multimedia engine, provides a richful API to store, load, decode and renderice multimedia in 3D environments like VULKAN and OPENGL" — [Source](https://www.curseforge.com/minecraft/mc-mods/watermedia/files/5921102); [Source](https://github.com/SrRapero720/watermedia)
- NGoedix/VideoPlayer "enhances your Minecraft server experience by allowing administrators to play videos directly in the GUI of all connected players", "Compatible with various video platforms, including YouTube and Twitch (Watermedia supported platforms)", plus "TV block, radio block and radio item to play videos in your survival" — [Source](https://github.com/NGoedix/VideoPlayer)
- VideoPlayer commands are "/playvideo <TARGETS/PLAYER> <VOLUME> <URL>" and "/playgovideo ..." with targeting, volume, position/size, fade in/out, non-skippable/non-controllable restrictions — [Source](https://www.curseforge.com/minecraft/mc-mods/video-player)
- LittleFrames (CreativeMD/LittleFrames) pitch is "pick any picture or video of the internet and bring it to Minecraft. You can choose the size, rotate or flip it", "No need for uploading files to the server (no need for storage) ... copy a link ... paste it into the frame. So all client will download the picture themselves. Also animated gifs are supported" — [Source](https://www.9minecraft.net/little-picture-frames-mod)
- LittleFrames CurseForge description adds "Powered by VLCJ" and "VLC 3+ is required to play videos" on older builds, now via WaterMedia dependency — [Source](https://www.curseforge.com/minecraft/mc-mods/littleframes)
- Modern Online Picture Frames: "Add images or GIFs to minecraft from the internet!", ~53–57 KB jars, Forge/Fabric/NeoForge builds — [Source](https://www.curseforge.com/minecraft/mc-mods/online-picture-frame/files/all)
- PicAxe (Picture Axe): "can put images from the internet onto beds, banners, a custom 6 sided block, and a sizable image frame", with "PicAxe Tool ... store your link", "Image Configurator ... control size, alignment, stretching ..., rotation, position offsets", "Resizable Image Frame ... 1x1 up to 6x6", "6-Sided Image Block ... different image [per] face", inspired by "the original Images mod" — [Source](https://www.curseforge.com/minecraft/mc-mods/picaxe)
- Projector Mod for Fabric: "client side mod that adds a custom picture block that can display images from the internet", "when installed as a server side mod, projector will sync the currently displayed images to all clients", "size ... controlled by placing picture blocks next to each other", "must be redstone powered", survival recipes (6x oak planks + redstone + glass = display; planks + button + iron + redstone torch = remote), works with Iris Shaders — [Source](https://github.com/HashiCraft/fabric-projector-mod)
- fabric-webstreamer (MaximumG9 fork of theorzr/fabric-webstreamer): "A Fabric mod to display web resources on screens, support for static images, HLS streaming in-game, including Twitch", "adds a single item ... called Web Display. It's a resizable and directional block that allows you to display HLS video streams but also static images", "supports two modes: raw HLS url (.m3u8 file) and Twitch channel with quality", "audio distance and volume is configurable" — [Source](https://github.com/MaximumG9/fabric-webstreamer1.21)
- webstreamer bundles FFmpeg + natives to "distribute a single JAR file" for "Linux arm64, Linux x86_64, OSX arm64 (M1), OSX x86_64, Windows x86_64" and warns "technology ... to get the video playing at the right frame rate with a synchronized audio ... might not work for all of you" — [Source](https://github.com/MaximumG9/fabric-webstreamer1.21)
- CinemaMod/CinemaMod: "Watch online videos with others in Minecraft. NOT RELEASED, IN DEVELOPMENT", blockers: "Need to convert CinemaMod to use MCEF 2", "Need to make a server backend for Fabric in addition to Bukkit", "Need to remove the hard requirement for ffmpeg to be installed on the server" — [Source](https://github.com/CinemaMod/CinemaMod)
- DarkSavci/Minecraft-Video-Player Paper plugin: "allows you to play videos/streams and paste images in Minecraft. It uses new thread to process videos/streams", commands "/processvideo [url]", "/processimage [url]", "/processstream", "/setres [width] [height] [fps]", claims 60fps on Ryzen 5 5600x, build via "mvn package -Djavacpp.platform=(your platform)", install on Paper/Spigot 1.19.4 — [Source](https://github.com/DarkSavci/Minecraft-Video-Player)
- Dream Displays: LGPLv3, Fabric/NeoForge/Quilt mod with "new packet protocol v2", "fallback support for protocol v1", "new playback modes", ~20.6 MB Fabric jar — [Source](https://www.curseforge.com/minecraft/mc-mods/dreamdisplays/files/8261946)

### Inferences
- Pixel-path taxonomy is stable: Chromium texture (interactive web), VLC/FFmpeg texture (passive video), direct URL-image texture (pictures/GIF/HLS) — server-rendered streaming is the outlier (WebDisplaysTogether only).
- Classic WebDisplays/MCEF gives interaction (click/scroll/JS) for free but inherently per-client desync; WATER/LittleFrames/VideoPlayer give cheap video but no shared browser state; Paper map plugins give vanilla fallback at cost of resolution/fps.
- Large-jar signal (~36–45 MB) reliably indicates bundled VLC/FFmpeg natives (WATERMeDIA, WebDisplaysTogether, Dream Displays, webstreamer); small jars (<250 KB) are URL-texture or MCEF-dependent mods.

### Gaps
- No reliable source found detailing exact texture-upload path (GL texture ID vs. map packets) for Modern Online Picture Frames, PicAxe, or Dream Displays renderers; would need source-code read.
- No reliable source confirming whether WATERFrAMES/LittleFrames do any playback-position sync or only URL sync; changelogs mention reconnect time-reset fixes but not full late-join semantics.

### Takeaway
MCEF-lineage always needs MCEF + downloaded Chromium natives (~100–200 MB) plus desktop OS; VLC-lineage needs WATERMeDIA/CreativeCore (+VLC) or bundled FFmpeg; image-frame mods are lightest (Fabric API/Architectury/Balm only); Fabric 1.20/1.21 coverage is complete for VLC/image families but official WebDisplays stops at 1.20.1 Forge — 1.21.1/Fabric comes only from community forks.

## For server-authoritative playback with late-join sync and vanilla fallback, what is reusable vs must be rebuilt?

### Takeaway
WebDisplaysTogether is the only citable server-authoritative reference (server Chromium + VP8/VP9/Opus stream + input forwarding); everything else syncs only URLs and leaves playback unsynced — so reuse its protocol/codec choices and WebDisplays block/peripheral model, reuse URL-image sync patterns from Projector/WATER/LittleFrames for fallback, and rebuild clock sync, late-join snapshots, and a Paper map-pack vanilla path (DarkSavci-style) from scratch.

### Cited Findings
- Only WebDisplaysTogether claims server-authoritative sync: "The web page runs on the server and is streamed to every player as video", "Clients only decode and display, and forward mouse/keyboard input back to the server; Every player sees exactly the same picture; logins are shared server-wide; playback is synchronized" — [Source](https://github.com/He-Horatio/WebDisplaysTogether); [Source](https://github.com/He-Horatio/WebDisplaysTogether/blob/main/README.md)
- WebDisplaysTogether late-join-relevant knobs: adaptive 360p–1080p/30fps from "server load and per-viewer network feedback", "Viewers can also pin a quality manually", config "screen size and resolution caps, stream fps/bitrate/height, concurrent browser limit, idle timeout, incognito, URL blacklist, home page, extra Chromium switches, miniserv port and quota" and client "render distance, MinePad resolution, music ducking" — [Source](https://github.com/He-Horatio/WebDisplaysTogether)
- Classic WebDisplays/Miniserv model to reuse for permissions/hosting: "per-screen permission system, and a built-in file host" with "miniserv port and quota" config — [Source](https://github.com/He-Horatio/WebDisplaysTogether)
- WATERFrAMES changelog shows the gap in client-side sync designs: "Fixed Displays resets time and log spams mismatchs when a player reconnects or joins the chunk" and "Fixed lagTickCorrection causes time jumps on media players without tick compensation ... proper fix will come with v3" — [Source](https://www.curseforge.com/minecraft/mc-mods/waterframes/files/7005589)
- LittleFrames/WATER model to avoid for sync: server stores URL only, "all client will download the picture themselves" with no server frame clock — [Source](https://www.9minecraft.net/little-picture-frames-mod)
- Projector gives the minimal URL-sync pattern worth copying: "when installed as a server side mod, projector will sync the currently displayed images to all clients" for static images — [Source](https://github.com/HashiCraft/fabric-projector-mod)
- VideoPlayer gives the server-command targeting pattern worth copying: "/playvideo <TARGETS/PLAYER> <VOLUME> <URL>" with targeting/volume/restrictions, but renders in GUI not synced world texture — [Source](https://github.com/NGoedix/VideoPlayer)
- Vanilla-fallback precedent: DarkSavci Paper plugin processes video/image/stream on a thread and serves via plugin commands without client mods (map/item-frame style path), with per-platform JavaCV natives — [Source](https://github.com/DarkSavci/Minecraft-Video-Player)
- 26.2 renderer risk for any custom GL path: "Developers making use of raw OpenGL calls rather than going through the Blaze3D API will need to migrate" for Vulkan — [Source](https://fabricmc.net/2026/06/15/262.html)
- License constraints on reuse: WebDisplaysTogether own code MIT but bundles "FFmpeg under LGPL v2.1+, JavaCPP under Apache 2.0" (NOTICE/licenses must ship in META-INF); MCEF LGPL allows proprietary use if unmodified; WATER/VideoPlayer ARR forbids vendoring — [Source](https://github.com/He-Horatio/WebDisplaysTogether); [Source](https://github.com/CinemaMod/mcef)

### Inferences
- Reusable directly: WebDisplays screen/peripheral/permission/Miniserv data model (MIT), WebDisplaysTogether server-render + VP8/VP9/Opus + speaker-block + incognito + quality-feedback design (MIT own code), Projector adjacency-scaling + redstone-gating + server URL-sync snippet (CC0), VideoPlayer target/volume/restriction command UX (idea only — ARR, do not copy code).
- Must rebuild: authoritative media clock with late-join catch-up (snapshot + seek-on-join + pause-on-empty-room), per-viewer jitter buffers, audit/blacklist + consent flow for shared logins, vanilla map-pack fallback renderer with downgraded fps/resolution, and Paper-side scheduler that survives restarts (none of the surveyed mods provide this combined).
- Do not reuse as library for this goal: per-client VLC/URL mods (desync by design), ARR/Custom/PolyForm Strict stacks (legal block on bundling), unreleased CinemaMod/CinemaMod (incomplete + hard ffmpeg-server requirement).

### Gaps
- No citable throughput/CPU-per-screen numbers for WebDisplaysTogether (only qualitative "scaled from server load"); capacity planning needs load testing.
- No reliable source on map-packet bandwidth limits or recommended fallback resolution/fps for vanilla clients; DarkSavci README claims 60fps on Ryzen 5 5600x but gives no player-count or network data.
- No source found for a maintained Paper + Fabric paired solution with shared protocol; Paper map plugins and Fabric screen mods are separate ecosystems and would need a new bridge.
