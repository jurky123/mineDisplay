# Vanilla map / display-entity image display reuse

## Which open source projects render images onto maps / ItemFrames? How do they do color quantization, dithering, map ID management?

### Takeaway
The reusable server-side image-to-map lineage is ImageOnMap (old, abandoned) → ImageMaps / ImageFrame (maintained); all split images into 128×128 tiles, quantize to the vanilla map palette (Bukkit `MapPalette` / NMS matching), and persist one map ID per tile plus metadata, with quotas/migration to bound ID growth.

### Cited Findings
- ImageMaps (`SydMontague/ImageMaps`): Bukkit plugin that "enables you to place custom images in your world by rendering them onto maps and placing them in item frames" for "info graphics, custom paintings and even the appearance of custom textures" — [Source](https://github.com/SydMontague/ImageMaps)
- ImageMaps license is MIT — [Source](https://github.com/SydMontague/ImageMaps)
- ImageMaps requires "a Server that implements Bukkit 1.13 or newer and the Spigot-API"; invisible/fixed frames need 1.16+, glowing frames need 1.17+ — [Source](https://github.com/SydMontague/ImageMaps)
- ImageMaps workflow: images live in `images/` folder (FTP copy or `/imagemap download <filename> <sourceURL>`); `/imagemap place <filename> [frameInvisible] [frameFixed] [frameGlowing] [size]` then right-click block for upper-left corner; `info`/`list`/`reload`/`delete` manage files — [Source](https://github.com/SydMontague/ImageMaps)
- ImageMaps tiling: "Images will by default split into 128x128 pixel sub-images to fit on a map. The image may be scaled via command parameters, however it is recommended to prepare correctly scaled images" — [Source](https://github.com/SydMontague/ImageMaps)
- ImageMaps quantization: "The color palette of Minecraft maps is very limited, requiring the plugin/Bukkit to convert the input image. This will result in your images looking different ingame than the source" with color-table link and `colorConversion.png` example — [Source](https://github.com/SydMontague/ImageMaps)
- ImageMaps persistence: stores placement in `maps.yml`; upgrading from <1.0.0 auto-converts `maps.yml` with backup attempt — [Source](https://github.com/SydMontague/ImageMaps)
- ImageMaps permissions `imagemaps.*/.place/.download/.delete/.info/.list/.reload/.help/.toggleFixed/.toggleVisible`, default OP; Maven `net.craftcitizen:imagemaps:1.0.1` via GitHub Packages — [Source](https://github.com/SydMontague/ImageMaps)
- ImageOnMap (`zDevelopers/ImageOnMap`): "load a picture from the Internet to a Minecraft map"; PNG/JPEG/static GIF; "saved on your server and reloaded at restart"; "Big pictures will be cut automatically into several parts ... 1024x1024 picture will be cut in 16 maps"; centered; splatter-map one-click wall deploy plus manual item-frame placement — [Source](https://github.com/zDevelopers/ImageOnMap)
- ImageOnMap license is CeCILL-B (BSD-style under French law) — [Source](https://github.com/zDevelopers/ImageOnMap)
- ImageOnMap commands: `/tomap <url> [resize|resize-stretched|resize-covered] [w h]`, `/maps` paginated GUI (retrieve/rename/delete/partial retrieve + usage quotas book), `/givemap`, `/maptool update/new/list/get/delete/explore/give/rename/migrate` — [Source](https://github.com/zDevelopers/ImageOnMap)
- ImageOnMap quotas/config: `map-global-limit`, `map-player-limit`, `limit-map-size-x/y` (0=unlimited), `save-full-image`, `collect-data`, per-player `imageonmap.mapLimit.XX`/`imageLimit.XX`, hosting allowlist + `imageonmap.bypasswhitelist`; comment "Images rendered on maps consume Minecraft maps ID, and there are only 32 767 of them" — [Source](https://github.com/zDevelopers/ImageOnMap)
- ImageOnMap 3.0 was "complete rewrite ... now based on QuartzLib" (incompatible with older maps, needs `/maptool migrate`); 4.x notes unify splatter map and prepare "required zLib features"; async rendering ("server won't freeze ... queue multiple renderings"), UUID management, i18n — [Source](https://github.com/zDevelopers/ImageOnMap)
- ImageOnMap version ceiling: "only compatible with Minecraft 1.15+" (4.0+); "For Minecraft 1.13 and 1.14, use 4.0-pre1"; 4.2.x tested on "Paper 1.17, 1.16 and spigot 1.17, 1.15", "no clue if this will work with 1.18 (it should, but we are not sure)" — [Source](https://github.com/zDevelopers/ImageOnMap)
- ImageOnMap distribution: SpigotMC 4.2.2 Jan 15 2022; CurseForge 166,540 downloads, last update Jan 15 2022, Game Versions listed, license Custom/GPLv3+ text "free software licenced under GNU GPL v3 or above, source on GitHub" — [Source](https://www.spigotmc.org/resources/imageonmap.26585); [Source](https://www.curseforge.com/minecraft/bukkit-plugins/imageonmap)
- ImageFrame (`LOOHP/ImageFrame`): "Put images on maps and walls!", links to Spigot 106031 / Modrinth / Hangar; "Built against Spigot's API ... usually also work with Paper"; Jenkins dev builds; Maven `com.loohp:ImageFrame` via `https://repo.loohpjames.com/repository` — [Source](https://github.com/LOOHP/ImageFrame)
- ImageFrame license is GPL-3.0 — [Source](https://github.com/LOOHP/ImageFrame)
- ImageFrame scope from Spigot page: animated GIF / "animated TV screen", map markers, survival-friendly, MySQL multi-server shared maps ("Plugin does not need to be installed on Bungeecord/Velocity proxy"), no dependencies listed besides server, overlay maps on held vanilla maps (`/imageframe overlay`), `clone`, `combined ImageMap` form (`get combined`), `rename/list/delete`, `marker add/remove/clear`, `setaccess`, `giveinvisibleframe`, `adminsetcreator`, `adminmigrate <ImageMap/DrMap/ImageOnMap>` — [Source](https://www.spigotmc.org/resources/imageframe-load-images-on-maps-item-frames-support-gifs-map-markers-survival-friendly.106031/)
- ImageFrame internals surface: `common/.../Commands.java` (~2256 lines) references `ImageFrame.imageMapManager.getFromCreator(...)`, `imageMap.rename(...)`, `ImageMapCreationTask`, async `Scheduler.runTaskAsynchronously`, Crowdin `languageManager`, `Updater.checkUpdate()` — [Source](https://github.com/LOOHP/ImageFrame/blob/main/common/src/main/java/com/loohp/imageframe/Commands.java)
- ImageFrame official addon: `ImageFrameClient` "Complementary client mod for servers with ImageFrame to display HD and full color images" — [Source](https://github.com/LOOHP/ImageFrame)
- ImageFrame NMS matrix: per-version modules `V1_16, V1_16_2, V1_16_4, V1_17, V1_18, V1_18_2, V1_19, V1_19_3, V1_19_4, V1_20, V1_20_2, V1_20_3, V1_20_5, V1_20_6, V1_21, V1_21_1 ... V1_21_11, V26_1, V26_1_1, V26_1_2, V26_2, V26_3` plus `abstraction/common` — [Source](https://github.com/LOOHP/ImageFrame)
- MapImage (`tommustbe12com/MapImage`): "/mapimage url" gives map from image URL (needs `https://`, server needs internet each startup, re-renders after restarts from lightweight YAML, no large image storage); "/mapimage url size HxW" multi-map matrix top-left→bottom-right; perm `mapimage.use` default OP; targets 1.20.x–1.21.x — [Source](https://github.com/tommustbe12com/MapImage); [Source](https://modrinth.com/plugin/mapimage)
- PaintedPixels (`antimyichael/PaintedPixels`): "upload an image through an online URL and receive a Minecraft map art that replicates the image ... automatically converts the image colors to match Minecraft's map color palette for a near 1:1 replica" — [Source](https://github.com/antimyichael/PaintedPixels)
- ReColorfulMap (`LunaDeerMC/ReColorfulMap`): "converts images into image maps, which can be hung on item frames ... remake of the original ColorfulMap ... original leaves a lot of images cache in plugins folder, and need to reload them every time the server starts" — [Source](https://github.com/LunaDeerMC/ReColorfulMap)
- InteractiveImage (`iM5LB/InteractiveImage`): "Paper plugin that turns ImageFrame maps into interactive UI panels — hover detection, visual effects, and click actions, all configured in-game ... requires ImageFrame" — [Source](https://github.com/iM5LB/InteractiveImage)
- ImageFrame Fabric port (`reyhe66243/ImageFrame-Fabric-Port`, GPL-3.0, created 2026-06-01, 222 commits): "server-side-only Fabric port ... for Minecraft 1.21+ ... 100% data compatibility with Spigot maps"; claims "Dynamic Map Color Engine: pixel-perfect Mojang NMS color matching ... No hardcoded palette files", "Network Visibility Cache: Maps and animation frames are only sent to players holding a map or standing within 32 blocks", invisible frames via invisibility splash/area-effect-cloud, Java 21+, `./gradlew build` in `fabric/` — [Source](https://github.com/reyhe66243/ImageFrame-Fabric-Port)
- ImageFrameMDE (`Zone-Infinity/ImageFrameMDE`): "intercepts image-loading commands and sends them to Discord for moderator approval"; supports 1.21.11 — [Source](https://github.com/Zone-Infinity/ImageFrameMDE)
- Bukkit rendering API surface: `MapRenderer(map, canvas, player)` abstract `render()` with contextual flag ("different canvases for different players"); `MapCanvas` 0–127 coords, `drawImage(x,y,Image)` clipped, `drawText` with `§<palette-index>;` colors, `get/setPixel`, `getCursors/getMapView` — [Source](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/map/MapRenderer.html); [Source](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/map/MapCanvas.html); [Source](https://github.com/Bukkit/Bukkit/blob/master/src/main/java/org/bukkit/map/MapRenderer.java); [Source](https://github.com/Bukkit/Bukkit/blob/master/src/main/java/org/bukkit/map/MapCanvas.java)
- Paper `MapPalette` "Represents the palette that map items use ... Each entry corresponds to four colors of varying shades"; byte-based `setPixel/getPixel` deprecated since 1.19/1.20.5 for removal in favor of `setPixelColor/getPixelColor(Color)`; pluggable `MapPalette.MapColorCache` — [Source](https://jd.papermc.io/paper/1.21.11/org/bukkit/map/MapPalette.html); [Source](https://jd.papermc.io/paper/26.2/org/bukkit/map/MapCanvas.html)
- Map-art quantizer references (browser tools, same palette problem): map-art-studio "A Minecraft map can store 61 base colors, each at four brightness levels. Flat ... single layer ... Staircase ... triples the palette to 183"; Floyd-Steinberg vs ordered vs none; "One 128 by 128 map is 16,384 blocks"; 2×2 ≈ 65,000 blocks — [Source](https://www.minecraftmaps.com/tools/map-art-studio)
- Map Art Converter: "fixed palette of about 244 colors (61 base colors × 4 shading levels), each pixel one block ... 128×128 blocks"; "4 shading levels: darker (Y descending south), normal, lighter (Y ascending south), darkest (underwater)"; Floyd-Steinberg toggle; Stretch/Cover/Contain fit — [Source](https://www.minecrafttoolkit.com/map-art)
- Loominary editor: grid "One map tile covers 128×128 pixels"; "Map palette quantizes every pixel ... with dithering" vs "Full color (sRGB) ... lossy AV1 stream"; palettes Flat fullblock 61 / Staircase fullblock 183 (shades 0–2) / All shades 244 (incl shade 3 "unobtainable via normal placement") / greyscale / carpet-only; dithers None/FS/Atkinson/Sierra/Sierra2/SierraL/Shiau/JJN/Stucki/Bayer; metrics OKLab/Chr+/Lum+/Hue/RGB; brightness/contrast/saturation pre-processing — [Source](https://zerohpminecraft.github.io/loominary/)
- MC Map Item Tool: color spaces LABA/RGBA/HSVA/XYZ; color schemes per MC version (1.7.2, 1.8.1, 17w06a, 1.12); dithering No/Floyd-Steinberg; interpolation Standard/Nearest; transparency threshold; compat New (1.16+) vs Legacy (≤1.15); dimension Overworld/Nether/End — [Source](https://mc-map.djfun.de/settings.html)

### Inferences
- For mineDisplay reuse, ImageFrame is the only full-featured maintained base (GIF, markers, overlays, MySQL, third-party migrator, per-version NMS abstraction); ImageMaps is the smallest readable MIT reference for tile-split + Bukkit-canvas rendering.
- Bukkit `drawImage`/`MapPalette.matchColor`-style nearest-color is the default path; quality-sensitive work should do its own resize + dither before calling canvas APIs, borrowing option sets from Loominary/map-art-studio rather than inventing new ones.
- Map-ID budgeting (quotas, `save-full-image=false`, YAML/DB stores, migrators) is load-bearing for any poster feature; prototype should enforce per-player and global caps from day one.

### Gaps
- Exact per-pixel matching/dithering code for ImageMaps, ImageOnMap (QuartzLib/zLib path), and LOOHP ImageFrame not verified from source in this pass; no reliable source found stating whether any of the three applies Floyd-Steinberg by default.
- No reliable source found for ReColorfulMap, MapImage, or PaintedPixels licenses, test coverage, or 1.21+/26.x behavior beyond short descriptions.
- No reliable source found for ImageFrame's on-disk/DB schema or GIF frame pacing/bandwidth knobs beyond feature-list level.

## Which projects use BlockDisplay/ItemDisplay/TextDisplay entities to show images in-world? Any reusable custom-model or resource-pack approaches for picture frames?

### Takeaway
No maintained reusable OSS was found that renders arbitrary images through vanilla display entities alone; the practical reusable paths are ItemDisplay + resource-pack `item_model` custom models (needs pack distribution) and the ImageFrameClient companion mod for HD/full-color (breaks pure-vanilla), while filled-map art still requires item frames because `item_display` cannot render map contents.

### Cited Findings
- Display entities "are entities useful for map or data pack creators ... Block Displays, Item Displays and Text Displays, used to display blocks, items and texts respectively"; Java Edition only; summoned via commands/structures, not natural gameplay — [Source](https://minecraft.wiki/w/Display)
- Item Displays "can display the model of any item placed into its contents slot"; "Using the item_model component on the contents item, you can display any model from a resource pack as long as it is defined by an item model definition file"; contents slot targetable by `/item` and `/loot`; rotation pivot is item-model center; block displays pivot at bottom-north-west corner; some blocks (end gateway, shulker boxes) use hardcoded renderers, fluids not displayed — [Source](https://minecraft.wiki/w/Display)
- Text Displays show formatted text components, single-sided by default, pivot bottom-center, default pixel 1/40th meter — [Source](https://minecraft.wiki/w/Display)
- Filled maps do not work in ItemDisplay: "Unfortunately, this can't be done with item_display because hand map rendering uses a completely different rendering method than regular items. The only way is to use item_frame with filling_map" — [Source](https://www.reddit.com/r/MinecraftCommands/comments/14rzvuk/displaying_a_map_through_item_display)
- Item frames are map-art's display vehicle across all major plugins: ImageMaps "rendering them onto maps and placing them in item frames" — [Source](https://github.com/SydMontague/ImageMaps); ImageOnMap "You can put your map in an item frame, or in multiple ones at once" plus invisible-frame-on-deploy option — [Source](https://github.com/zDevelopers/ImageOnMap); ImageFrame "Load Images on Maps & Item Frames", invisible-frame items, markers — [Source](https://www.spigotmc.org/resources/imageframe-load-images-on-maps-item-frames-support-gifs-map-markers-survival-friendly.106031/)
- Resource-pack picture path without maps: ImageTitles (MIT, Modrinth) "Replace Minecraft titles with custom images. Create a resource pack with the images and you'll be able to display them" via `/title` JSON — [Source](https://modrinth.com/mod/imagetitles)
- HD/full-color path that drops vanilla-only: ImageFrameClient is the "Complementary client mod for servers with ImageFrame to display HD and full color images" — [Source](https://github.com/LOOHP/ImageFrame)
- Full-color AV1 path: Loominary "Full color (sRGB) keeps true 24-bit colour; exported as a lossy AV1 stream. Requires the next Loominary release (or newer) to view in-game" vs map-palette path "Editable pixels quantized to Minecraft map colours" — [Source](https://zerohpminecraft.github.io/loominary/)
- Unrelated NeoForge client/server mod name collision: `Dseelis/ImageFrame` "press Shift+Right-click on a frame and insert a link to an image or GIF", PNG/JPG/GIF ("Not everything is displaying properly"), 3,539 downloads, 1.21.1 NeoForge, All Rights Reserved — [Source](https://www.curseforge.com/minecraft/mc-mods/imageframe)
- World-to-image renderers (mcmap/MinedMap/Mapcrafter/Overviewer) render saves to web tiles/isometric views and are not image-to-map display libraries — [Source](https://github.com/spoutn1k/mcmap); [Source](https://github.com/neocturne/MinedMap); [Source](https://github.com/mapcrafter/mapcrafter)

### Inferences
- mineDisplay's vanilla-client Phase 1 should stay on maps-in-item-frames; display entities add value only as scalers/positioners for framed maps or as TextDisplay labels, not as image raster surfaces.
- Any "HD picture frame" via ItemDisplay + `item_model` + pack textures is a separate pack-distribution feature (PackHost-adjacent), not a drop-in vanilla join-and-see poster.

### Gaps
- I found no reliable source for an actively maintained open-source library that pages video frames through Block/Item/TextDisplay entities with a vanilla client; if one exists it did not surface under display-entity/picture-frame queries.
- No reliable source found for performance/quality comparisons of ItemDisplay+custom-model frames vs map-art posters (entity cost, pop-in, resolution caps).

## What are the hard limits (128x128 per map, map palette, entity counts, map ID growth, per-player visibility)?

### Takeaway
One map is a 128×128 byte-indexed image in a per-ID `map_<#>.dat` file; usable palette is ~61 base colors × usable shades (61 flat, ~183 staircase, 244 with unobtainable shade), every poster tile costs entities/frames plus a permanent map ID, and per-player truth requires contextual renderers or packet filtering.

### Cited Findings
- Resolution/storage: `colors` is "Width * Height array ... (16384 entries for a default 128×128 map)", indexed `Colors[widthOffset + heightOffset * width]`, top-left origin; files are GZip'd NBT `map_<#>.dat` in world `data/` dir; `idcounts.dat` tracks latest map ID — [Source](https://minecraft.wiki/w/Map_item_format)
- Map NBT: `scale` 0–4 ("in 2^scale wide blocks square per pixel, even for 0, where the map is 1:1"), `dimension` (Nether renders as unreadable static), `trackingPosition/unlimitedTracking/locked/xCenter/zCenter`, `banners` and `frames` marker lists — [Source](https://minecraft.wiki/w/Map_item_format)
- Palette mechanics: "Each material has a base color that is multiplied by 135, 180, 220 or 255, and then divided by 255"; "to get the first map color ID for a base color, multiply the base color ID by 4 (ID 0 has 4 gradients of itself despite them all being transparent)" — [Source](https://minecraft.wiki/w/Map_item_format)
- Base-color roster current wiki lists IDs 0 NONE (transparent) through 61 GLOW_LICHEN with RGB and block mapping (e.g. 1 GRASS 127,178,56; 12 WATER 64,64,255; 29 COLOR_BLACK 25,25,25; 60 RAW_IRON; 61 GLOW_LICHEN 127,167,150) — [Source](https://minecraft.wiki/w/Map_item_format)
- Flat vs staircase: "flat method ... smaller palette of only 61 colors. The staircase method offers 183 colors, but is much more complicated"; slope rule (higher than block north = lighter, lower = darker; partial blocks like carpet set color only above full block; water depth bands) — [Source](https://minecraft.wiki/w/Map_item_format); [Source](https://minecraftonline.com/wiki/Canvas_and_Palette)
- Consumer-tool restatement: flat single-height full-block 61, staircase full-block 183 (shades 0–2), all-shades 244 incl shade 3 unobtainable normally; carpet-only 16-color subsets — [Source](https://zerohpminecraft.github.io/loominary/); [Source](https://www.minecraftmaps.com/tools/map-art-studio); [Source](https://www.minecrafttoolkit.com/map-art)
- Per-map block cost: "One 128 by 128 map is 16,384 blocks if you fill it edge to edge", counted per-color in stacks of 64; 2×2 grid ≈ 65,000 blocks — [Source](https://www.minecraftmaps.com/tools/map-art-studio)
- Map-ID pressure: ImageOnMap config comment "Images rendered on maps consume Minecraft maps ID, and there are only 32 767 of them" with global/player/size/full-image-saving quotas as mitigation — [Source](https://github.com/zDevelopers/ImageOnMap)
- Frame/entity cost: item frames are placeable-on-sides/top/bottom entities holding one map each (one entity + one map ID per 128×128 tile); invisible/fixed/glowing frame flags are version-gated (1.16+/1.17+) — [Source](https://github.com/SydMontague/ImageMaps)
- Server render path is packet/canvas based: Paper `CraftMapRenderer.render` iterates 128×128 `worldMap.colors` into `canvas.setPixel` then rebuilds `MapCursorCollection` from `worldMap.decorations`, skipping vanished players via `player.canSee` — [Source](https://github.com/PaperMC/Paper/blob/main/paper-server/src/main/java/org/bukkit/craftbukkit/map/CraftMapRenderer.java)
- Per-player divergence: `MapRenderer(boolean contextual)` — contextual true means "different canvases for different players" — [Source](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/map/MapRenderer.html)
- Visibility/bandwidth control example: Fabric port "only sent to players holding a map or standing within 32 blocks of an active map frame" to cut packet overhead for large servers/animated frames — [Source](https://github.com/reyhe66243/ImageFrame-Fabric-Port)
- Companion client evidence that vanilla maps are bandwidth/quality capped: HD/full-color needs ImageFrameClient mod; AV1 full-color needs matching Loominary release — [Source](https://github.com/LOOHP/ImageFrame); [Source](https://zerohpminecraft.github.io/loominary/)
- Inventory-preview gap: maps normally paint only when held/near; Show My Maps plugin/mod exists precisely to paint inventory/chest/ground tooltips because "It cannot conjure maps you have never been sent" (per-server disk cache of received maps, Paper 1.21.1–26.2 jar + Fabric client) — [Source](https://modrinth.com/plugin/show-my-maps)

### Inferences
- Budget rule of thumb: N tiles = N map IDs + N item-frame entities + N×16,384 palette indices; a 4×3 wall is 12 IDs/entities before any video-frame multiplier, so video must reuse IDs (frame updates) rather than mint maps per frame.
- Staircase 183-color quality is a physical build technique (height steps), not available to pure `MapCanvas` painting; canvas plugins are effectively flat-palette (~61 + dither), which bounds photo quality without client mods.

### Gaps
- No reliable version-specific source found in this pass for the current (26.x) maximum map-ID type/range or `idcounts.dat` behavior change since the old 32,767 comment; modern code suggests int IDs but not confirmed here.
- No reliable source found for hard server caps on item frames/display entities per chunk or packet-size/frequency limits for animated map updates.

## Which of these are actively maintained and compatible with modern versions (1.20+/1.21+)? Which are abandoned?

### Takeaway
ImageFrame is the only map-image project verified active into 2026/26.x; ImageMaps shows 2025 life; ImageOnMap is stale since 2022; small 2025–2026 satellites (MapImage, Fabric port, NeoForge mod, MDE gate) cover 1.21+ niches but are tiny or proprietary-licensed.

### Cited Findings

### Inferences
- Default choice for 1.21+/26.x server-side posters is ImageFrame (GPL-3.0 obligations apply); ImageMaps (MIT) is the better code-reading/forking base if mineDisplay needs a minimal owned implementation.
- ImageOnMap should be treated as a migration source (via ImageFrame `adminmigrate`) rather than a dependency.

### Gaps
- No reliable source found confirming ImageMaps or any fork is tested on 1.21/26.x beyond the 2025 1.0.11 anecdote; modern compatibility is inferred from Bukkit-API-only design, not verified.
- No reliable source found for ReColorfulMap, PaintedPixels, or InteractiveImage last-release dates or supported versions in this pass.
