# MineDisplay 实施计划

2026-10-01 · 提案。当前仅完成仓库与文档，以下功能全部未实现。按阶段独立发布，不把 M4 视频能力写成 M1 已支持。

## M0：技术验证与构建基线

- 创建最小 Gradle Paper 工程，沿用 Java 25、26.2、相邻项目的依赖/命名习惯；锁定真实可下载版本。
- 验证 MapRenderer + ItemFrame、四朝向地图墙、重登后的地图更新、地图 ID 重用与区块载入行为。
- 记录 Paper 每玩家实体隐藏 API 在目标版本的行为，为混合后端做可行性验证。
- 小型 Fabric 渲染原型验证 26.2 世界平面、纹理释放、深度测试；不提前搭通用框架。
- 调研 Java 25 可用解码绑定、三平台分发与许可证，写选型记录；视频正式依赖延后到 M4。

验收：最小插件可加载；原版客户端显示一张自定义图片；原型测得地图发送行为；不改兄弟插件。
阻塞：目标 API 不可用时修订设计，不通过私有/NMS API 偷渡既定方案。

## M1：原版静态图片（首个可发布版本）

交付：本地 PNG/JPEG 导入、素材索引、地图墙创建/绑定/删除、保护、权限、持久化、list/info/status 命令。
实现 DisplayManager、MediaStore 与地图渲染的最小结构；主线程不执行 IO/解码；有界转换任务与原子发布。
支持保持比例/裁剪、四墙朝向、16 tiles 单屏上限和 128 tiles 全局上限。

验收：

- 1×1、2×2、4×4 四朝向图案无镜像/接缝，透明背景一致；无资源包与 mod 可看。
- 导入失败/创建一半失败不遗留实体和记录；替换图不增长 map ID。
- 重登、重启、区块卸载/重载后不复制屏幕；破坏/旋转/取图被保护，普通玩家不能控制。
- 5 个静态墙、10 个观察者的代表场景测量 MSPT、堆内存、流量，静态图不逐 tick 重发。
- `./gradlew build` 与相关单测通过，Paper 实机验证记录在发布文档。

## M2：轮播与 MineUI 静态 HUD

交付：轮播列表、停留时长、暂停/续播；MineUI 业务 API 管理页与图片 HUD；无 MineUI 聊天管理回退。
HTTPS 导入默认关闭，开启时有域名白名单、SSRF/重定向/解码尺寸检查。HUD 素材需受控 HTTPS 分发；没有托管地址时世界地图功能继续工作。
图片 HUD 先验证 MineUI 支持的格式和版本，不开放未校验的图片格式。

验收：旧 MineUI/mod 不支持时明确降级；不改变其他插件 scoreboard；权限撤销、轮播替换与异步完成无陈旧状态覆盖。
轮播不使用视频级发送频率，任务/纹理释放验证通过。

## M3：高清世界屏幕与混合能力

交付：protocol 模块、Fabric 客户端、握手/能力位、HTTPS 下载缓存、高清世界平面、距离/视锥/世界裁剪、本地隐藏设置。
媒体服务采用配置的受控站点，部署与鉴权流程完整；客户端缓存摘要校验与 LRU 有界。
地图与高清按玩家区分，先 READY 再切换；目标版本若隐藏行为不可靠先交付独立 client 屏幕并更新兼容表。

验收：原版、仅 MineUI、仅 MineDisplay、两种 mod 四种矩阵均可正确显示或降级；没有重叠屏幕与隐私越权。
断线、换世界、快速进出范围、连续替换 100 次素材后引用/纹理不持续增长；损坏摘要/离线站点有封面回退。
客户端版本化安装包仅包含本项目产物；三平台实机支持范围按验证结果公布。

## M4：视频（第二个主要发布目标）

前置：明确原生库选择和许可证、解码分发支持、受控媒体 HTTPS 可用；不要求兄弟插件新增 API。
交付：离线转码工具、manifest/profile、封面、本地有界解码、世界视频/视频 HUD、服务端时间轴、play/pause/seek/loop、迟到定位、音轨/静音/音量/距离衰减。
先短片静音，再长片，再有声同步；逐阶段记录预算，不能凭短片测试宣布电影支持。

验收：

- 720p/30 FPS 单路目标在已公布基线机器上持续 30 分钟测量平均/低分位 FPS、CPU、RAM/VRAM、缓存与下载流量。
- 2 路可见视频触发有界资源管理；超过上限退到封面；一个有声源，离开停止声音。
- 两客户端晚加入、pause/resume/seek/loop、服务器低 TPS、时钟校正、缓冲失败、revision 乱序均可恢复。
- 稳态播放误差目标 ≤250 ms；达不到时公布实测并调整目标/profile，不能隐瞒偏差。
- 不安装 mod 展示封面；解码错误/缺原生库可继续使用图片功能；退出后 native/GPU/音频资源释放。
- 三平台分别构建与实机确认后才声明支持；不支持平台给明确错误和图片回退。

## M5：可选扩展（不作为完整基础方案的阻塞）

实验低帧率地图动画、预制 ItemDisplay 资源包屏幕、播放列表编排、第二个业务调用方推动公开 API。
直播/HLS/门户上传/跨服同步作为新需求评估。MineUI 视频组件和 MineAudio 外部时钟需单独确认跨项目变更。

## 验证与发布策略

文档阶段只检查链接、设计一致性、Git 注册与敏感文件排除，不声称执行不存在的构建。
代码阶段每阶段按 README 构建和相关单测；真实渲染、网络与音视频不能用单元测试替代实机验证。
性能基线记录 Minecraft/Paper/mod 版本、硬件、分辨率、人数、屏幕数、素材时长和测量工具。
插件与 mod 使用同一发行版本，协议独立版本；不兼容客户端显式回退；回滚保留旧素材与配置备份。
首版依赖只有实际需要的项目；新增依赖说明目的、许可证、维护状态和分发方式。

## 尚待产品选择

默认先保证原版地图图片，再完成可选 mod 视频。首次实施前可调整优先级，但不影响本次规划交付。
待确定：主要用途是大厅公告还是电影院、典型人数/屏幕数、原版视频是否确有需求、受控 HTTPS 托管位置、支持的客户端系统。
这些选择影响 M3/M4 容量与交付范围；M1 静态图片不依赖它们。
